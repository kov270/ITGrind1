# ITGrind1 — банковские счета, дни 1–2

Учебный Python-проект о наследовании, абстрактных классах,
переопределении методов и полиморфизме. Деньги и ставки хранятся в Decimal.

## Запуск

```powershell
python -m src.main
```
Демонстрация показывает обычные операции, запрет операций с замороженным
счётом, начисление процентов, минимальный остаток, разницу лимитов,
овердрафт с комиссией, погашение долга и инвестиционный прогноз.
Ожидаемые ошибки обрабатываются через try / except.

## Типы счетов

`AbstractAccount` хранит ID, номер, владельца, защищённый по соглашению
баланс `_balance` и статус. Он объявляет обязательные методы `deposit()`,
`withdraw()`, `get_account_info()`. Создать его напрямую нельзя.
Проверки выполняют конкретные классы с помощью функций из utils.py.

| Класс | Особенности | Значения по умолчанию |
|---|---|---|
| BankAccount | Пополнение и снятие без отрицательного остатка | Лимит одного снятия 100 000 |
| SavingsAccount | Минимальный остаток и месячные проценты | Минимум 0, ставка 1%, лимит снятия 100 000 |
| PremiumAccount | Повышенный лимит и овердрафт с фиксированной комиссией | Лимит снятия 500 000, овердрафт 5 000, комиссия 500 |
| InvestmentAccount | Портфель stocks, bonds, etf и прогноз доходности | Пустой портфель, лимит снятия 100 000 |

Лимиты и комиссия выражены в валюте счёта. Валюты: RUB, USD, EUR, KZT, CNY.
Валюта по умолчанию — RUB, конвертации нет.
Статусы: active, frozen, closed; задаются при создании.
Денежные операции разрешены только для active.

ID — полный UUID. Номер счёта — строка ровно из 12 цифр 0–9.
Если номер не задан, он формируется из числового UUID с нулями слева.

## Примеры

```python
from src.models import BankAccount, SavingsAccount, PremiumAccount, InvestmentAccount

ordinary = BankAccount("Иван", balance=1000)
ordinary.deposit("250.50")
ordinary.withdraw(100)
print(ordinary.get_account_info()["balance"])  # 1150.50

savings = SavingsAccount(
    "Ольга", balance=10000, monthly_rate="0.01", min_balance=1000
)
print(savings.apply_monthly_interest())  # 10100.00
print(savings.withdraw(9100))  # 1000.00 — ровно минимальный остаток

premium = PremiumAccount(
    "Сергей", balance=1000, overdraft_limit=5000, overdraft_commission=500
)
print(premium.withdraw(1500))  # -1000.00 с учётом комиссии
print(premium.deposit(200))  # -800.00 — частичное погашение
print(premium.deposit(800))  # 0.00 — полное погашение

investment = InvestmentAccount("Мария", balance=10000)
investment.invest("stocks", 5000)
investment.invest("bonds", 3000)
investment.invest("etf", 1000)
rates = {"stocks": "0.10", "bonds": "0.04", "etf": "0.07"}
print(investment.project_yearly_growth(rates))  # 690.00
```

`get_account_info()` возвращает словарь; `print(account)` использует `__str__()`.
Поля денег и ставок в словаре имеют тип Decimal. Для JSON их нужно
преобразовать в строки. У инвестиционного счёта возвращается копия портфеля.

## Правила расчётов

Для дробных сумм и ставок передавайте строки или Decimal: "25.50", "0.015".
Целые числа принимаются напрямую. Float поддерживается через Decimal(str(value)),
но погрешность, возникшую в предыдущем вычислении float, это не исправляет.

Суммы операций положительные, начальный баланс и минимальный остаток могут
быть нулевыми. Введённые деньги с долями меньше копейки отклоняются.
Ставки передаются долями: "0.01" — 1%, "0.015" — 1.5%.
Месячная ставка строго положительная; годовые прогнозные ставки могут
быть положительными, нулевыми и отрицательными.

Сложение и вычитание выполняются без округления. Начисленные проценты
и годовой прогноз округляются до копейки по ROUND_HALF_UP:
0.005 становится 0.01, -0.005 становится -0.01.
Для доходности используется localcontext() с точностью 50 значащих цифр.
Суммы и баланс ограничены модулем меньше 10^18. Ставки — модулем меньше
10^18, не более 28 значащих цифр и показателем десятичной степени не ниже -28.

Накопительный счёт нельзя создать с балансом ниже min_balance.
Каждый вызов apply_monthly_interest() выполняет одно начисление:
время и повторные начисления за тот же месяц не отслеживаются.

Премиальная комиссия берётся за каждое снятие, после которого баланс
отрицательный, в том числе если счёт уже был в минусе. При нулевом или
положительном результате комиссии нет. Комиссия входит в проверку
лимита овердрафта. Пополнение долга не облагается этой комиссией.

invest() переносит деньги из свободного баланса в портфель.
withdraw() снимает только свободные деньги, продажи активов нет.
project_yearly_growth() возвращает ожидаемый прирост, не начисляет его
на баланс; ставка нужна для каждого актива с ненулевыми вложениями.

## Ошибки

- InvalidOperationError — некорректные данные, превышение лимита снятия
  или нарушение минимального остатка.
- AccountFrozenError — операция над замороженным счётом.
- AccountClosedError — операция над закрытым счётом.
- InsufficientFundsError — недостаточно средств или превышен овердрафт.

Специальные ошибки наследуются от InvalidOperationError, а он — от ValueError.

## Ограничения учебной модели

Данные существуют только в памяти. Проверки уникальности номеров в хранилище,
авторизации, переводов, продажи активов и конкурентных операций пока нет.
Подчёркивание в `_balance` — соглашение, а не запрет доступа;
атрибуты следует менять через предусмотренные операции.
Сокращённые номера на основе UUID могут совпасть.
