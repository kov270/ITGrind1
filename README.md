# ITGrind1 — банковские счета, дни 1–5

Учебный Python-проект о наследовании, абстрактных классах,
переопределении методов и полиморфизме. Деньги и ставки хранятся в Decimal.

## Запуск

```powershell
python -m src.main
```
Демонстрация показывает обычные операции, запрет операций с замороженным
счётом, начисление процентов, минимальный остаток, разницу лимитов,
овердрафт с комиссией, погашение долга и инвестиционный прогноз.
Ожидаемые ошибки обрабатываются через try / except.
В демонстрации создаются по два накопительных, премиальных и инвестиционных
счёта; с каждым выполняются операции.
Для дня 3 регистрируются Иван, Анна и Мария, каждому открываются счета.
Показаны заморозка и разморозка, отказ в снятии с замороженного счёта,
блокировка после трёх неверных входов, отказ даже с правильным паролем
после блокировки, успешный вход после одной ошибки и запрет доступа к чужому счёту.

## Клиент — начало дня 3

`Client` хранит ФИО, UUID (`client_id`), возраст, контакты, статус
и список номеров счетов `account_numbers`. Возраст — целое число от 18 лет.
Контакты задаются непустым словарём с непустыми строковыми ключами и значениями.
Статусы клиента: `active` и `blocked`. Список счетов изначально пуст.

```python
from src.models import Client

client = Client(
    "Иван Петров Сергеевич", 18,
    {"phone": "+79991234567", "email": "ivan@example.com"},
)
print(client.full_name)
print(client.account_numbers)  # []
```

Формат телефона и email пока не проверяется. Bank связывает клиента со счетами;
owner счёта хранит ФИО клиента строкой.

## Управление банком — день 3

`Bank` хранит клиентов и счета в словарях. `add_client(client, password)`
регистрирует объект Client и сохраняет соль и PBKDF2-хеш пароля.
`authenticate_client(client_id, password)` возвращает True или False.
Три последовательные неудачные попытки блокируют клиента; успешный вход
сбрасывает счётчик. Для операций нужно сначала войти.

```python
from src.models import Bank, Client

bank = Bank()
client = Client("Анна Смирнова", 20, {"phone": "+79990000000"})
bank.add_client(client, "example-password")
if bank.authenticate_client(client.client_id, "example-password"):
    account = bank.open_account(client.client_id, "savings", balance=1000)
    bank.freeze_account(client.client_id, account.account_number)
    print(bank.search_accounts(client.client_id, status="frozen"))
    bank.unfreeze_account(client.client_id, account.account_number)
```

Типы для open_account: bank, savings, premium, investment.
Дополнительные именованные аргументы передаются конструктору нужного счёта.
Владелец берётся из Client. Номера внутри банка не повторяются.
close_account требует активный счёт, нулевой баланс и пустой портфель.
Закрытый счёт остаётся в истории. Поиск возвращает информацию только о счетах
вошедшего клиента; фильтры — точный account_number и status.

Вход сохраняется в памяти экземпляра Bank: это простая учебная модель.
У счетов, открытых через Bank, денежные операции проверяют доступ и время
даже при прямом вызове account.deposit()/withdraw()/invest().
get_total_balance() возвращает свободные остатки всех счетов по валютам.
get_clients_ranking(currency="RUB") возвращает список клиентов по убыванию
суммы их счетов в выбранной валюте. Долги уменьшают итог; замороженные счета
и заблокированные клиенты учитываются, потому что их деньги не исчезают.
Инвестиционный портфель не входит в свободный баланс.
Клиент без счетов выбранной валюты получает нулевую сумму;
при равенстве сумм сохраняется порядок регистрации.
Пустой банк возвращает {} для баланса и [] для рейтинга.
Эти общебанковские отчёты предназначены для локального управляющего кода:
проверка роли администратора пока отсутствует. Они доступны и ночью.
Методы для завершения сеанса и разблокировки не добавлялись.

### Защита

- Три последовательные ошибки входа блокируют клиента. Успешный вход
  обнуляет счётчик; неверный вход снимает прежнюю отметку авторизации.
- bank.suspicious_actions возвращает копию журнала: время, ID клиента,
  действие, причина и номер счёта. Пароли и их хеши в журнал не записываются.
- Отмечаются неверные входы, попытки доступа без авторизации,
  обращения к чужим счетам, обращения заблокированных клиентов и ночные операции.
- С 00:00 включительно до 05:00 исключительно по Asia/Colombo (UTC+05:30)
  запрещены открытие, закрытие, заморозка, разморозка, пополнение, снятие,
  инвестиции и начисление процентов. Регистрация, вход, просмотр и прогноз
  доступны ночью.

Bank() использует реальные часы. Bank(now=функция) позволяет подставить часы
для проверки интервала. datetime с часовым поясом переводится в Asia/Colombo;
без пояса трактуется как время банка. В main.py часы банка демонстрационные:
показаны отказ в 00:00 и разрешение в 05:00.

Отдельные счета, созданные без Bank для упражнений дней 1–2, не получают
его ограничения. Это модель одного процесса: ручное изменение внутренних
полей Python не считается защищённым интерфейсом.

## Транзакции — день 4

В src/transactions.py находятся Transaction, TransactionQueue и TransactionProcessor.
Transaction хранит UUID, тип, сумму, валюту, отправителя, получателя,
комиссию, статус, причину отказа, число попыток и временные отметки UTC.
Валюта операции совпадает с валютой отправителя. Денежные поля — Decimal.

```python
from src.transactions import Transaction, TransactionQueue, TransactionProcessor

# bank — банк с зарегистрированным и вошедшим клиентом;
# sender и recipient — счета, открытые через этот банк.
queue = TransactionQueue()
transaction = Transaction(
    client.client_id, sender.account_number, recipient.account_number,
    amount="100.00", currency="RUB",
)
queue.add(transaction, priority=10)
processor = TransactionProcessor(bank, queue)
processor.process_ready()
print(transaction.status, transaction.failure_reason)
```

Очередь хранится обычным списком. Больший priority выполняется раньше;
при равенстве сохраняется порядок добавления. execute_at — datetime
с часовым поясом: до этого времени операция не выбирается.
queue.cancel(transaction_id) отменяет ожидающую операцию или ожидающий повтор.
Завершённые, отменённые и отказанные операции не выбираются заново.

Типы: internal_transfer — внутри одного Bank, external_transfer — в другой
объект Bank, указанный в recipient_bank. Неизвестный номер вызывает отказ.
Фиксированная внешняя комиссия по умолчанию 10 единиц валюты отправителя.
При использовании овердрафта дополнительно применяется комиссия PremiumAccount.
Комиссии списываются сверху: получатель получает конвертированную сумму перевода.
Пара курсов ("RUB", "USD") задаёт количество USD за один RUB.
Курсы передаются вручную; автоматического обратного курса нет.

Bank.transfer() проверяет условия и рассчитывает оба новых баланса до записи.
В однопоточной модели отказ не изменяет ни один баланс. Учитываются статусы
обоих счетов, ночной запрет, лимит отправителя, минимум SavingsAccount и
овердрафт PremiumAccount. Получателю не требуется вход для получения денег.

TemporaryTransactionError допускает до 3 попыток всего с задержкой 60 секунд
по умолчанию. Остальные ошибки дают окончательный failed. Журнал processor.errors
хранит ID, попытку, время, тип ошибки и причину. При успешном повторе текущая
причина отказа очищается, предыдущая ошибка остаётся в журнале.
Задержки не используют sleep: нужно снова вызвать process_ready(), когда
придёт время. Для проверки внешнего сбоя есть external_available — функция bool.

main.py запускает 10 транзакций с управляемыми часами: 5 завершаются,
4 получают ожидаемый отказ, 1 отменяется. Есть приоритет, конвертация,
овердрафт, отсрочка на 2 минуты и успешный повтор внешнего перевода.
Состояния: created → pending → processing → completed / failed / retry_pending;
ожидающие операции также можно перевести в cancelled.

## Аудит и риск — день 5

`src/audit.py` содержит AuditLog, RiskAnalyzer, RiskBlockedError и перечисления:
AuditLevel (info, warning, error, critical), RiskLevel (low, medium, high).
Каждый Bank получает свой анализатор и файл `logs/audit-<bank_id>.jsonl`.
Папка logs исключена из Git. Пароли и хеши в аудит не записываются.

AuditLog хранит события в памяти и дописывает JSONL-файл. При открытии
существующего файла читает сохранённые записи. filter() поддерживает точные
фильтры по важности, клиенту, транзакции, событию, риску и интервалу времени.
Границы since/until — datetime с часовым поясом, обе включительно.
Для уровней можно передать Enum или его строковое значение.

```python
from src.audit import AuditLevel

warnings = bank.audit_log.filter(level=AuditLevel.WARNING)
suspicious = bank.audit_log.suspicious_operations()
profile = bank.risk_analyzer.client_profile(client.client_id)
errors = bank.audit_log.error_statistics()
```

Риск анализируется в Bank.transfer(), поэтому проверяются как переводы
через TransactionProcessor, так и прямой bank.transfer(). Оценка выполняется
до списания; при high возникает RiskBlockedError и оба баланса сохраняются.
Medium отмечается, но сам по себе не блокирует операцию.
Прямые deposit(), withdraw() и invest() сохраняют свои проверки доступа,
статуса и времени; поведенческая оценка RiskAnalyzer к ним пока не подключена.

Настраиваемые учебные правила по умолчанию:

| Сигнал | Баллы |
|---|---:|
| Сумма не меньше крупного порога | 3 |
| Сумма не меньше половины порога, но ниже полного | 1 |
| От 10 операций клиента за 60 секунд, включая текущую | 3 |
| От 5 до 9 операций за 60 секунд | 1 |
| Перевод новому получателю | 1 |
| Время банка 00:00–04:59:59 | 3 |

0 баллов — low, 1–2 — medium, от 3 — high с блокировкой.
Пороги крупных сумм: RUB 100000, USD 1000, EUR 1000, KZT 500000, CNY 10000.
Это параметры упражнения, а не нормативы реальных банков.
Получатель становится знакомым после успешного перевода. Учитываются банк
и номер получателя. Частота считается по клиенту, включая разные счета;
одна транзакция с несколькими попытками учитывается один раз.
Анализированные отказы тоже входят в частоту. Операции, отвергнутые до
стадии анализа, например из-за неизвестного номера, в это окно не входят.

Профиль содержит число оценённых и успешных переводов, блокировки,
распределение уровней, причины и число знакомых получателей.
Уровень профиля — максимальный за всю историю анализатора, не только
за последнюю минуту. Журнал ошибок считает каждую неудачную попытку отдельно.
Файловые ошибки отражаются в audit_log.file_errors; запись остаётся в памяти
с persisted=False. Сбой диска не превращает выполненное списание в отказ.

main.py показывает 8 переводов с учебным порогом 1000 RUB: 4 успеха,
3 блокировки риска и один отказ из-за заморозки. История риска хранится
в памяти и не восстанавливается из файла аудита при перезапуске.

## Перечисления Enum

Фиксированные варианты собраны в `src/enums.py`:
ClientStatus, AccountStatus, AccountType, Currency, AssetType,
TransactionType, TransactionStatus, AuditLevel, RiskLevel,
RiskReason, SecurityReason, AuditEvent и OperationAction.

```python
from src.enums import AccountStatus, Currency, AssetType
from src.models import InvestmentAccount

account = InvestmentAccount(
    "Анна", balance=1000, status=AccountStatus.ACTIVE, currency=Currency.RUB
)
account.invest(AssetType.STOCKS, 100)
print(account.status.value)  # active
```

Старые входные строки также принимаются: status="active", currency="rub",
asset="stocks". check_enum() преобразует строку в элемент нужного перечисления;
check_currency() дополнительно переводит код валюты в верхний регистр.
Неизвестное значение и Enum другого типа вызывают InvalidOperationError.
Внутри объектов статусы, валюты, активы, типы транзакций и уровни риска — Enum.
get_account_info(), общие отчёты, журнал безопасности и JSONL возвращают
обычные строковые значения для совместимости. Причины риска Transaction — RiskReason.
Для логики сравнивайте с элементом Enum, для отображения используйте .value.
Произвольные сообщения ошибок, имена и номера не являются перечислениями.
TextEnum добавляет строковое поведение и вывод значения через __str__(),
поэтому print(account.status) также показывает active.

## Типы счетов

`AbstractAccount` хранит ID, номер, владельца, защищённый по соглашению
баланс `_balance` и статус. Он объявляет обязательные методы `deposit()`,
`withdraw()`, `get_account_info()`. Создать его напрямую нельзя.
Проверки выполняют конкретные классы с помощью функций из utils.py.

| Класс | Особенности | Значения по умолчанию |
|---|---|---|
| BankAccount | Пополнение и снятие без отрицательного остатка | Лимит одного снятия 100 000 |
| SavingsAccount | Минимальный остаток и месячные проценты | Минимум 0, ставка 1%, лимит снятия 100 000 |
| PremiumAccount | Повышенный лимит и овердрафт с фиксированной комиссией | Лимит снятия 500 000, овердрафт 5 000, комиссия 500 |
| InvestmentAccount | Портфель stocks, bonds, etf и прогноз доходности | Пустой портфель, лимит снятия 100 000 |

Лимиты и комиссия выражены в валюте счёта. Валюты: RUB, USD, EUR, KZT, CNY.
Валюта по умолчанию — RUB, конвертации нет.
Статусы: active, frozen, closed; задаются при создании.
Денежные операции разрешены только для active.

ID — полный UUID. Номер счёта — строка ровно из 12 цифр 0–9.
Если номер не задан, он формируется из числового UUID с нулями слева.

## Примеры

```python
from src.models import BankAccount, SavingsAccount, PremiumAccount, InvestmentAccount

ordinary = BankAccount("Иван", balance=1000)
ordinary.deposit("250.50")
ordinary.withdraw(100)
print(ordinary.get_account_info()["balance"])  # 1150.50

savings = SavingsAccount(
    "Ольга", balance=10000, monthly_rate="0.01", min_balance=1000
)
print(savings.apply_monthly_interest())  # 10100.00
print(savings.withdraw(9100))  # 1000.00 — ровно минимальный остаток

premium = PremiumAccount(
    "Сергей", balance=1000, overdraft_limit=5000, overdraft_commission=500
)
print(premium.withdraw(1500))  # -1000.00 с учётом комиссии
print(premium.deposit(200))  # -800.00 — частичное погашение
print(premium.deposit(800))  # 0.00 — полное погашение

investment = InvestmentAccount("Мария", balance=10000)
investment.invest("stocks", 5000)
investment.invest("bonds", 3000)
investment.invest("etf", 1000)
rates = {"stocks": "0.10", "bonds": "0.04", "etf": "0.07"}
print(investment.project_yearly_growth(rates))  # 690.00
```

`get_account_info()` возвращает словарь; `print(account)` использует `__str__()`.
Поля денег и ставок в словаре имеют тип Decimal. Для JSON их нужно
преобразовать в строки. У инвестиционного счёта возвращается копия портфеля.

## Правила расчётов

Для дробных сумм и ставок передавайте строки или Decimal: "25.50", "0.015".
Целые числа принимаются напрямую. Float поддерживается через Decimal(str(value)),
но погрешность, возникшую в предыдущем вычислении float, это не исправляет.

Суммы операций положительные, начальный баланс и минимальный остаток могут
быть нулевыми. Введённые деньги с долями меньше копейки отклоняются.
Ставки передаются долями: "0.01" — 1%, "0.015" — 1.5%.
Месячная ставка строго положительная; годовые прогнозные ставки могут
быть положительными, нулевыми и отрицательными.

Сложение и вычитание выполняются без округления. Начисленные проценты
и годовой прогноз округляются до копейки по ROUND_HALF_UP:
0.005 становится 0.01, -0.005 становится -0.01.
Общая точность Decimal — 50 значащих цифр. Она задаётся через
getcontext().prec = 50 при импорте utils.py. Округление до копеек задаётся отдельно.
Это настройка текущего контекста выполнения; приложение использует один поток.
Суммы и баланс ограничены модулем меньше 10^18. Ставки — модулем меньше
10^18, не более 28 значащих цифр и показателем десятичной степени не ниже -28.

Накопительный счёт нельзя создать с балансом ниже min_balance.
Каждый вызов apply_monthly_interest() выполняет одно начисление:
время и повторные начисления за тот же месяц не отслеживаются.

Премиальная комиссия берётся за каждое снятие, после которого баланс
отрицательный, в том числе если счёт уже был в минусе. При нулевом или
положительном результате комиссии нет. Комиссия входит в проверку
лимита овердрафта. Пополнение долга не облагается этой комиссией.

invest() переносит деньги из свободного баланса в портфель.
withdraw() снимает только свободные деньги, продажи активов нет.
project_yearly_growth() возвращает ожидаемый прирост, не начисляет его
на баланс; ставка нужна для каждого актива с ненулевыми вложениями.

## Ошибки

- InvalidOperationError — некорректные данные, превышение лимита снятия
  или нарушение минимального остатка.
- AccountFrozenError — операция над замороженным счётом.
- AccountClosedError — операция над закрытым счётом.
- InsufficientFundsError — недостаточно средств или превышен овердрафт.

Специальные ошибки наследуются от InvalidOperationError, а он — от ValueError.

через main.py. requirements.txt не содержит внешних зависимостей.
Начните чтение с main.py, затем переходите к models.py и utils.py.

## Ограничения учебной модели

Данные существуют только в памяти. Проверки уникальности номеров в хранилище,
полноценных многопользовательских сеансов, подключения к внешним банкам, продажи активов
и конкурентных операций пока нет.
Подчёркивание в `_balance` — соглашение, а не запрет доступа;
атрибуты следует менять через предусмотренные операции.
Сокращённые номера на основе UUID могут совпасть.
